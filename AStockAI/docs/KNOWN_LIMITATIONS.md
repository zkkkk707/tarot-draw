# 已知技术限制

## 数据源

1. **AKShare 不是交易所授权行情**。它是开源的数据接口封装库，底层抓取东方财富、新浪等公开网页接口。接口可能因上游网页改版而变化、限流或暂时不可用；代码对必需字段做了显式校验，变化时会报错并记录，而不是静默产生错误数据。请遵守各数据提供方的使用条款，不要调低请求间隔。
2. **全A快照没有行情时间戳**。`stock_zh_a_spot_em` 只返回价格等字段，没有逐笔时间，因此快照的 `data_status` 是 `unknown_time`，实时性未经验证。系统用三种方式弥补：记录本地获取时间；交易时段内内容长时间不变判为 `stale`；用带时间戳的自选股分钟K交叉核对（`spot_crosscheck`）。
3. **全A快照请求量较大**。新版 AKShare 的全A快照会在函数内部分页请求（每页约 100 条，共数十次请求），本项目只能限制两次函数调用之间的间隔，无法控制函数内部的分页频率。默认 60 秒一次，不建议调得更短。
4. **请求超时**：AKShare 多数接口未设置超时。本项目为 `requests` 注入了默认超时（连接 5 秒、读取 20 秒），但对不使用 `requests` 的接口无效；分页接口的总耗时也可能超过单次超时。
5. **集合竞价**：只在 09:25–09:30 采集一次集合竞价结果快照；09:15–09:25 的竞价过程数据取决于数据源，本系统不采集。
6. **市场宽度为派生数据**：由全A快照统计得到；涨停/跌停家数按涨跌幅限制估算（主板10%、ST 5%、创业板/科创板20%、北交所30%），新股无涨跌幅限制期、注册制下 ST 规则差异等情况会导致偏差，因此字段名带 `_approx`。
7. **行业板块**使用东方财富行业分类；成分每日刷新一次，日内的成分调整不会实时反映。

## 指标与筛选

8. **前复权价格会随时间变化**。默认使用前复权（qfq）日K；发生除权除息后，历史上所有前复权价格都会整体调整。系统会检测到不一致并重新获取完整历史，但这意味着：用今天的前复权数据回测过去，价格水平与当时实际看到的并不相同（比例关系基本保持）。严格回测建议改用后复权（`daily_adjust: "hfq"`）或保存不复权数据并自行做时点复权。
9. **两种量比口径**：快照中的 `volume_ratio` 是数据源提供的盘中量比（按分钟折算）；指标中的 `volume_ratio_5d` 是日线口径（当日量 ÷ 前5日均量），二者不可混用。
10. **RSI 初值**：用 α=1/N 的递推平均实现 Wilder 平滑，以第一个有效值为初值，与“前 N 日简单平均作初值”的写法在前期有细微差异，约 3N 个交易日后收敛。
11. **盘中筛选使用前一交易日指标**：盘中价格来自最新快照，但均线/RSI/MACD 等来自上一交易日收盘，避免使用未完成的当日K线；因此盘中的“价格>MA20”等判断是“现价相对昨日均线”。
12. **催化与基本面**：V1.0 没有接入可靠的新闻、公告、财务数据源，该项一律标记为缺失，不计分。评分模型本身是初始研究假设，未经回测验证。
13. **首次使用需要回填**：首次运行时约 1 年的全A日K需要数千次请求（预计 1 小时以上，只在非交易时段进行）；回填完成前，量价、风险收益等依赖历史的评分项会显示为缺失。

## 运行环境

14. **内存硬限制的口径边界**：详见 `MEMORY_CONTROL.md` 第 5 节。
15. **程序停止后数据不再更新**：work_data 文件保留最后一次的内容，`manifest.json` 中的 `freshness` 也停留在最后一次写入时的判断。读取时务必用 `expires_at`、`writer.heartbeat_expires_at` 与当前北京时间比较。
16. **文件被占用**：Windows 上若其它程序以独占方式打开了 work_data 中的文件，原子替换可能失败；系统会有限次重试，失败时保留旧文件并在 manifest 中标记 `last_write_failed`。
17. **直接关闭控制台窗口**属于非正常退出：数据不会损坏，但当前批次中断，`manifest.json` 中 `writer.running` 会停留在 `true`（请以 `heartbeat_expires_at` 判断）。
18. **交易日历**来自新浪数据，通常覆盖到当年年底；跨年后新一年日历发布前，会临时按工作日判断并标记 `fallback_weekday`，此时若遇到节假日，快照内容不变会被判为 `stale`。
19. **系统时钟**：所有时间以运行电脑的系统时钟为准，请保持 Windows 自动校时开启。
20. **2GB 预算会删除最旧数据**：数据量超出预算时，会按日期从最旧开始删除，包括日K线。如果 `.venv` 较大、留给数据库的空间不足以保存 1 年日K，可用历史就会少于 1 年，MA60 等长周期指标仍能计算（只需约 3 个月），但可回看的历史会变短。`market_status.json` 的 `storage_budget` 会显示实际占用情况。
21. **2GB 是整个文件夹的预算**：不包括 Python 本体（安装在系统目录）、pip 下载缓存（在用户目录）以及系统临时目录中 SQLite 全量 VACUUM 产生的临时文件。
22. **未经运行验证**：本次交付的全部代码未被执行（见 README 第 13 节）。
